# 待办识别评测方法

这份文档说明**怎么测**、**测什么**、结果放在哪。结果本身由测试自动生成，
落在 `docs/todo-recognition-eval-result.md`，不手工维护。

## 为什么要有这一套

待办识别的产物会进入用户的日程。这类功能有两个特点，决定了它必须被量化：

1. **错一条的代价远大于漏一条。** 凭空多出来的待办要用户自己发现并清理；
   而漏掉一条，用户顶多回到原来的手动录入。所以误报要单独算，且目标是 0。
2. **改动是持续的。** 每加一条确定性规则、每改一次模型提示词或阈值，都可能
   在别处引入误报。没有固定语料就只能靠“感觉还行”，而感觉在这件事上系统性偏乐观。
3. **一次输入不等于一条任务。** 两个可独立完成、改期或删除的事项必须分别计分；
   只判第一条正确而漏掉第二条，不能算整条用例通过。

## 两层结构

识别分两层，评测也按两层记：

| 层 | 位置 | 依据 | 什么时候用 |
| --- | --- | --- | --- |
| 本地确定性层 | `ClipboardTodoExtractor` + `TodoReconciler` | 正则、词表、最长公共子串 | 对获准处理的内容先跑，免费且可核验 |
| 模型层（few-shot） | `AIFeature.todoRevision` | 绝对时间上下文、现有待办、来源摘录、结构化多决策输出 | 拖入、显式收纳、固定后的 Mac 内容、通用剪贴板 |

模型层是主语义理解器，不再要求本地词表先认出某个场景。这样“赶回合肥”、
“看完项目并写完论文”这类开放表达不会被封闭词表挡在模型外。本地层仍承担两项职责：

- 模型不可用时提供确定性回退；
- 对每个模型决策逐项验证编号、结构化码、证据、动作白名单、数量上限与冲突。

## 语料

`Tests/MnemoCoreTests/TodoRecognitionCorpus.swift`，当前 52 条，五组：

- **码类**（取餐码 / 取件码 / 快递 / 验证码）——字面命中，属于“确凿”档；
- **截止与日程**——标题靠从整句里做减法抠出来，属于“要问一句”档；
- **改期 / 取消 / 完成**——要和现有待办对上号；
- **多任务拆解 / 去重**——一段输入返回多条独立提案，重复事项只保留一条；
- **干扰**——代码、网址、闲聊、第三方主语、只共用通用词。误报全在这一组暴露。

每条带期望结论、一句说明“这一条想守住什么”，以及 `needsModel` 标记。该标记
表示本地确定性层结构上做不到，不是允许失败；两版在这些用例上的差值就是 few-shot
的净收益。多任务期望使用 `creates(titleContains:)`，会同时核对条数和每个独立标题。

## 判定口径

| 结果 | 含义 |
| --- | --- |
| correct | 动作、对象、时间、任务条数都对 |
| falsePositive | 期望什么都不做，却给出了至少一条结论 |
| missed | 期望有结论，却什么都没给 |
| wrong | 给了结论，但动作、对象、时间、条数或拆分结果不对 |

“准确率”只在**本地层可覆盖子集**上算（排除 `needsModel`），否则这个数字会
随着往语料里加模型难题而下降，看不出确定性层是否退化。

## 怎么跑

项目使用 Xcode beta 工具链；为避开 iCloud Desktop 给构建产物附加 xattr，测试使用
`/tmp` 下的新 scratch 路径：

```bash
scratch=$(mktemp -d /tmp/mnemo-swiftpm-tests.XXXXXX)
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  swift test --scratch-path "$scratch"

# 跑完并导出报告
scratch=$(mktemp -d /tmp/mnemo-swiftpm-eval.XXXXXX)
MNEMO_EVAL_REPORT=docs/todo-recognition-eval-result.md \
DEVELOPER_DIR=/Applications/Xcode-beta.app/Contents/Developer \
  swift test --scratch-path "$scratch" --filter exportsReport
```

不设 `MNEMO_EVAL_REPORT` 就不写文件——普通测试不该改动工作区。

## 硬约束

测试里各有对应断言，破了就红：

1. **误报为 0**（`localLayerHasNoFalsePositives`）；
2. **可覆盖子集全对**（`localLayerCoversItsSubset`）；
3. **单条耗时 < 20 ms**（`recognitionStaysFast`）；
4. **多任务逐项保留**：批量解析最多 5 项、去重、坏项不拖掉好项、同一旧待办
   一批最多修改一次；
5. **安全边界不随批量输出放宽**：真实 ID 不出域，确认后仍保留来源，改名/完成/
   取消必须明确点 ✓，设置里的“直接加入”只授权新建。

## 怎么产出 few-shot 那一列

模型层需要用户配置的供应商凭据，因此联网实测不作为普通单元测试前置条件。两部分
各自验证：

**不需要凭据的部分**（`TodoRevisionPromptTests`）：

- 输出协议是 `{"decisions":[...]}`，同时兼容旧单对象；
- 每项独立校验，越界编号或字段不完整只丢掉自身；
- 结果去重并限制为最多 5 项；
- 同一条现有待办一批最多接受一个动作；
- 现有待办只给编号，不给真实 ID；
- evidence / code 继续针对原始文字验证；
- few-shot 明确覆盖“今天要看完项目并写完论文”拆成两条且共享同一绝对日期。

**需要凭据的部分**：在设置的「AI 功能」页给「待办协调」配置供应商与模型，
然后对 `needsModel` 用例逐条走真实链路，将结果记录到报告第二列。当前 7 条：

| 用例 | 本地层为什么做不到 |
| --- | --- |
| due-11 | “发我”不是本地截止线索词 |
| due-13 | 个人出行表达不依赖固定场景词 |
| due-14 | 聊天上下文里的隐含截止任务 |
| due-15 | 餐饮状态 + 订单号，没有“取餐码”字样 |
| rev-17 | “那个报告的事”是指代，标题对不上号 |
| rev-18 | “报告”是通用片段，本地相似度主动拒绝 |
| multi-01 | 一个相对日期同时修饰两个开放语义动作，需要模型拆解 |

同时要验证反方向：模型接入后，本地原本判对的 45 条不能被带坏。误报为 0 的约束
对模型同样成立。

## 加用例的时机

只在**有真实输入让它出错**的时候加，不凭空造。每加一条要写清楚它守的是什么；
写不出来的多半是重复用例。修 bug 时先加用例再改代码——否则无法证明这次真的修好，
也无法防止下次改回去。
