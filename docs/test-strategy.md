# Test Strategy：Mnemo 新版本

## 1. 测试方案总览

### 1.1 用例分类规则

| 前缀 | 类别 | 覆盖对象 |
|------|------|----------|
| `N-` | 正常 | 主流程在预期输入下的行为，一条 AC 至少一条 |
| `B-` | 边界 | 临界时间、空集合、极值输入，以及旧库迁移兼容边界 |
| `F-` | 失败 | design 第 10 节边界情况表逐条对应，一行一条，不合并 |
| `R-` | 回归 | 首版已上线功能在本版改动后不退化 |

用例总数 96 条：N 42、B 11、F 36、R 7。F 用例数量与 design 边界表行数严格相等。

### 1.2 测试环境

| 项 | 值 |
|----|----|
| 系统 | macOS 26，具体版本 `[运行后填入]` |
| 机型 | 带刘海的 MacBook，型号 `[运行后填入]` |
| 对话供应商 | MiniMax（指定）。协议方言为 **Anthropic Messages**，非 OpenAI 兼容 |
| baseURL | 国内 `https://api.minimaxi.com/anthropic/v1`；国际 `https://api.minimax.io/anthropic/v1` |
| 快模型 | `MiniMax-M2.5`，输入 0.3 / 输出 1.2，上下文 204800，输入模态仅 text |
| 强模型 | `MiniMax-M3`，输入 0.3 / 输出 1.2，上下文 1048576，输入模态 text·image·video |
| embedding 供应商 | 阿里云百炼（DashScope）。协议方言为 **OpenAI 兼容**，baseURL `https://dashscope.aliyuncs.com/compatible-mode/v1`，环境变量 `DASHSCOPE_API_KEY` |
| embedding 模型 | `qwen3.7-text-embedding`。该模型不在 models.dev 与 LiteLLM 任一目录中，须手动填入；输出维度由运行时探测得出，实测值 `[运行后填入]` |
| 对照方言 | 百炼同时充当 N-18 的 OpenAI 兼容方言对照，无需第三家供应商 |
| 凭据来源 | 环境变量 `MINIMAX_API_KEY` 与 `DASHSCOPE_API_KEY`，由 gitignored 的本地文件加载。**任何 key 不得写入本文档、测试脚本或仓库** |

MiniMax 同一家内 M2 系列仅支持 text、M3 支持 image，这一差异正好用作能力门控（F-18）的测试样本，无需跨供应商构造。

### 1.3 测试数据准备

| 数据集 | 内容 |
|--------|------|
| 文本 | 普通中文段落；含身份证号（校验位合法）；含银行卡号（Luhn 合法）；含形如 `sk-` 的密钥串；长度超过 1048576 token 的超长文本 |
| 文件 | 0 字节文件；普通 PDF；外置卷文件；需托管的临时文件；正好 50MB 与 50MB 减 1 字节的旧库兼容样本；500MB 视频；无扩展名二进制 |
| 图片 | 含中英文混排文字的截图 |
| 时间分布 | 昨天与今天各创建若干条，覆盖文字 / 图片 / 链接 / PDF 四种类型 |

## 2. 模块 1：刘海交互与视觉

| # | 输入 | 预期输出 | 验证点（关联 AC） |
|---|------|----------|-------------------|
| N-01 | 启动 25 分钟番茄钟后收起刘海 | 状态条显示剩余时间，格式为 `mm:ss`，每秒递减 | 计时状态优先于默认入口（AC-01） |
| N-02 | 拖拽一个文件进入刘海命中区，随后移开不释放 | 命中时只展开浅层投放区并覆盖计时状态；移开立即恢复原状态，不打开完整工作台 | 拖拽状态优先级与浅层投放（AC-01） |
| N-03 | 普通指针停在刘海 5 秒，再单击刘海；随后点击面板外并用 Esc 各关闭一次 | hover 期间不展开；单击才展开；外部点击与 Esc 都能收起 | 显式点击开合（AC-02） |
| N-04 | 分别在文本编辑未保存、已钉住两种状态下点击面板外 | 编辑态出现二次确认且内容不丢失；钉住态保持展开 | 关闭保护条件独立生效（AC-03） |
| N-05 | 空闲态观察刘海下方，再在 0、1、多条上下文推荐下点击展开唇、复制和关闭图标并录屏 | 展开唇稳定开合；单条留翼；多条首行位于物理刘海与展开唇下方；复制 / 关闭不展开；工作台打开时锚点不可见 | 动态几何与单一点击所有权（AC-04） |
| N-06 | 切换至效率模式，退出 App，重新启动并展开 | 展开后仍处于效率模式 | 模式状态持久化（AC-05） |
| N-07 | 番茄钟计时结束 | 刘海边缘出现呼吸光；在设置中关闭该项后重复一次，不再出现 | 边缘光效及其开关（AC-26） |
| B-01 | 系统开启「减弱动态效果」后重复 N-05 | 过渡降级为无动画的直接切换，不出现 morph | 辅助功能降级路径（AC-04） |
| B-02 | 指针沿刘海边缘和菜单栏连续往返 10 次，不点击、不拖拽 | 面板高度始终不变，不出现展开或投放态 | hover 不改变窗口状态（AC-02） |
| F-34 | 构造拖拽悬停与番茄钟计时同时成立 | 状态条只显示投放区，不并列、不轮播 | 有序枚举取最高优先级（AC-01） |
| F-35 | 在无刘海机型运行，或改变主屏配置 | 回退为屏幕顶部居中的锚定条，仍仅点击展开；全部功能可用，不崩溃、不显示空白刘海区 | design 边界：无刘海环境 |

## 3. 模块 2：收纳与存储

| # | 输入 | 预期输出 | 验证点（关联 AC） |
|---|------|----------|-------------------|
| N-08 | 拖入任意体积的普通 Finder PDF，确认标注为「引用」，随后删除源文件并执行健康检查 | 原文件存在时从原路径预览；确认删除后 Pin 自动进入回收站，旧向量冻结，不保留一张失效空卡片 | 引用优先与确认删除（AC-06） |
| N-09 | 从外置卷拖入文件，卸载该卷后再重新挂载 | 卷离线期间 Pin 保留且冻结后台处理，不误删、不要求重新定位；卷恢复后可再次打开 | 暂时不可达与确认删除分离（AC-06） |
| N-10 | 同一份需托管的临时文件连续拖入三次，删除后再次拖入 | 库中只有 1 个 Pin，沙盒中只有 1 份内容，引用计数为 1；再次拖入恢复相同条目 ID 与冻结向量 | 内容级去重与回收站恢复（AC-07） |
| N-11 | 删除一条已索引的文字条目，在回收站中恢复 | 条目回到库中；其 `indexedAt` 与删除前一致，未触发重算 | 回收站保留向量（AC-08） |
| N-12 | 库内含受管副本与回收站条目时打开存储用量面板 | 面板显示的副本占用总量与 `du -sh` 结果差值小于 1MB；活跃副本与回收站分别计数；有界内存缩略图缓存不虚报为磁盘占用 | 用量统计口径（AC-10） |
| N-13 | 执行整库导出，在全新用户目录下导入 | 条目数量、副本文件数、标签数、分组数与源库逐项相等 | 导出导入完整性（AC-27） |
| N-14 | 打开一条文本条目的编辑器，输入至 28 字，点确认 | 头部字数随输入实时更新为 `28 字`；确认后内容写回，`contentHash` 与 `indexedAt` 均更新 | 编辑写回与字数（AC-37） |
| N-15 | 打开编辑器修改内容后点取消 | 改动全部丢弃，条目内容与打开前逐字相同 | 取消语义（AC-37） |
| N-41 | 连续复制 7 条内容，把其中 1 条固定，再由 Mnemo 自己复制一条卡片 | 临时剪贴板轨道动态保留最近 5 条未固定项；固定项不淘汰；Mnemo 自己写入剪贴板的内容不被再次捕获 | 剪贴板容量、固定保护与去回环（AC-45） |
| N-43 | 外部复制“给我发一张央视新闻报道牛来的图片” | 本地判为图片检索且**不入库**；请求套话不进入 embedding；共享语义索引召回真实截图；模型收敛到唯一一条时自动写入剪贴板并在写成功后显示对号 | 快捷路径与主动搜索同源、唯一结果自动准备 |
| N-46 | 复制“央视关于牛来报道的图片”（无请求动词） | 本地按短名词短语推断为检索并给出推荐；找到结果后原文撤出历史，什么都没找到时原文仍留在最近五条 | 推断查询的两级判据 |
| N-61 | 复制“pi agent 网址给我”（词表里既没有场景词也没有可识别标识） | 形态闸门放行并做一次本地召回；库里确有该链接时给出推荐，没有则安静，不再因为词表缺词而整条静默 | 判据泛化到词表之外 |
| N-63 | 在访达复制一个文件；随后按 ⌃⌘P，再把同一文件拖进刘海 | 复制不产生任何条目；⌃⌘P 与拖入都正常入库 | 被动监听只收截图与文字 |
| N-62 | 复制一句与库中内容毫无关系的短话 | 证据不足，不显示任何推荐，也不动剪贴板轨道 | 证据闸门 |
| N-60 | 把"终端使用指南"存成一条文字，再复制“我要终端使用指南” | 带类型召回为空后自动退回不限类型，仍能推荐到那条文字；与搜索页结果一致 | 类型只作偏好不作墙 |
| N-54 | 库里同时存在含 test-time 的文字与图片时，复制“带有 test-time 的图” | 只召回图片；文字条目因类型过滤不进候选 | 类型词表单一来源 |
| N-57 | 在收纳与效率两种模式下观察展开面板 | 卡片保持单行且完整可见，任何一排都不被内容区裁切；模式切换不改变窗口 frame；效率页表盘与统计条不被裁切 | 面板密度（AC-04、F1.6） |
| N-58 | 双击一条链接卡片；分别在有封面与只有站点图标两种情况下观察 | 有封面时整块铺开并在左下角显示站点、标题与地址；只有站点图标时用域名徽标铺底而不是把图标拉满；右上角动作条可复制、就地看页面、在浏览器打开、关闭 | 链接预览 |
| N-59 | 打开「更多」下拉；另在卡片多于一屏时悬停卡片轨道 | 下拉完全落在面板轮廓内，不盖住刘海与菜单栏；轨道两侧出现翻页把手且能前后翻页 | 面板内弹层与轨道可达性 |
| N-56 | 锁定一条剪贴板内容后再点一次图钉 | 图钉常驻可见并在两种状态间切换；取消后立刻重新参与五条淘汰 | 固定可逆（AC-45） |
| N-55 | 在卡片上分别单击与双击 | 单击复制并给出已复制反馈；双击打开预览，不误触发复制之外的动作 | 单击复制、双击打开 |
| N-53 | 复制“带有 test-time 的图给我”；另在剪贴板路由未配置模型的情况下重复一次 | 两次都进入检索：前者靠"请求词 + 具体标识"本地判定，后者在路由无人应答时仍做一次本地召回；诊断文件记录走了哪一条 | 推荐不因词表或路由缺位而静默 |
| N-47 | 复制“研究生数学建模的手册”；再复制一句本地词表完全认不出的短诉求 | 前者本地即判为检索、不入库并给出推荐；后者交由模型路由裁决；成段正文两者都不触发也不调用模型 | 本地词表不再是唯一闸门 |
| F-36 | 未授予完全磁盘访问权限时，从微信聊天里拖入一个文件 | 明确提示读不到及两条出路（授权后重启 / 先存到访达），并展开工作台让提示可见；不留下读不出内容的空壳 Pin | TCC 拦截的显式降级 |
| N-52 | 从微信聊天里拖入一个文件后查看卡片 | 缩略图右下角出现微信图标，tooltip 写明来源；从访达拖入的条目没有角标 | 来源应用角标 |
| N-51 | 从微信聊天里把一个 PDF 拖进刘海，随后复制它并粘到访达 | 入库即保存受管副本而非书签（对方不给读时改走文件承诺或拖拽板字节）；复制出来的是带原文件名的可读文件；若确实读不到则明确报错并提示重新拖入，不出现"已复制却粘不出来" | 受保护来源必须留副本 |
| N-50 | 复制一个受管副本型 PDF 与一张剪贴板图片，分别粘进访达、微信和聊天网页输入框 | 粘出来是带原始文件名和扩展名的文件；图片在只认位图的输入框里也能直接粘 | 暂存命名与图片数据（AC-45 相关） |
| N-49 | 前台停在别的应用，点击推荐行的复制图标与右翼的关闭 | 一次点击即生效，不需要先激活 Mnemo；复制成功后该行变成对号；关闭只撤卡片不展开 | 锚点点击由 AppKit 独占 |
| N-48 | 在任意应用选中一段文字按 ⌘G | 刘海直接给出推荐（不展开工作台）；代按的 Cmd-C 不产生剪贴板条目 | 选区推荐与自写去回环 |
| N-66 | 分别对文档、图片、网页、表格、日志、代码和普通文字提出“给我原对象”与“解释 / 总结 / 分析内容”的成对请求 | Few-shot 按最终产物分别返回 `retrieve / answer`；answer 的证据 ID 不显示原对象卡；聚焦输入框时 SSE 直写，否则完整中文回答自动写剪贴板，成功才显示对应确认 | 跨内容类型意图、互斥输出与回答自动交付 |
| N-67 | 分别选中“pi agent 的网址”和“把 CSA-UD 论文发我”按 ⌘G | 控制器返回 `retrieve`；前者只复制本地逐字校验的网址，后者交付真实文件；两者不生成解释 | 交付意图与本地载荷安全 |
| B-15 | Mock OpenAI 返回 `finish_reason=length`、Anthropic 返回 `stop_reason=max_tokens` | 两种半成品都不发布；显示可重试的回答失败状态 | 回答完整性 |
| B-16 | 连续两次不同 Command-G 请求并记录请求体 | 每次只有本轮新 system/user 与本轮证据；前一轮 messages / tool state 不出现在后一轮，旧回答不覆盖新剪贴板 | Agent 轮次隔离与剪贴板竞态 |
| N-68 | 生成一条完整回答，分别模拟剪贴板写入成功 / 失败；滚动长回答并点击外部 | 成功自动复制并显示“已放进剪贴板”；失败保留正文与复制重试；回答无叉号、点外部收起；正文裁剪不覆盖标题，自绘细滑块悬浮右边界且无槽无框 | 回答自动交付与轻量滚动 UI |
| N-69 | 快速连续按 Command-G 100 次，并让两次 Cmd-C 异步交错；再重复同一请求命中控制器缓存 | 每次按键都生成新 token，无冷却或次数阈值；只有最新抓取可发布；精确登记实际 changeCount；等待期间的 Mnemo 自写回答被拒绝；缓存重放仍显示处理中 | 连续触发、选区竞态与缓存反馈 |
| N-70 | 在“选中文字即自动复制”的应用中先选中内容，生成回答自动覆盖剪贴板，再保持选区连续按 Command-G | 第一次可用外部自动复制基线；后续可用 AX 当前选区或同一前台应用显式选区记忆；不提示过期；Mnemo 回答不会反向成为查询 | Command-C / 自动复制与 Command-G 兼容 |
| N-65 | 检索进行中点击面板外收起，稍后重新展开 | 检索继续跑完，结果与回答仍在原地；不出现空白 | 收起不取消检索 |
| B-14 | 让模型返回两条候选；另构造银行账号 / 证件号意图的唯一命中 | 两条时只推荐不自动写；敏感意图即便唯一也只推荐 | 自动写入的边界 |
| N-44 | 初步候选 A、B，模型有效返回仅 A，再返回有效空数组 | 首次 B 消失；第二次卡片清空；未知 ID 不出现 | 模型白名单为最终集合 |
| B-12 | 分别构造推荐 JSON 格式错误与重排服务不可用 | 格式错误保留本地搜索结果并提示；服务不可用时剪贴板只回退到类型匹配且有真实证据的候选 | malformed / unavailable 分离 |
| N-45 | 复制包含请求文字的图片，等待 Vision OCR；处理中再复制另一内容 | OCR 落库后触发上下文管线；旧 generation 不覆盖新剪贴板或发布旧卡片 | 图片 OCR 与竞态保护 |
| B-13 | 唯一 PDF 异步解析 URL；分别让文件不可用、取消事件和写入失败 | 只有写入成功才显示对号；失败保留普通复制按钮；旧事件不覆盖新内容 | 自动复制事实状态 |
| B-03 | 仅通过旧库迁移入口 `.automaticBySize` 导入体积正好等于 50MB 的记录 | 按历史规则归引用侧；新 UI 不调用该入口 | 旧阈值数据兼容，不代表新入库产品规则 |
| B-04 | 仅通过旧库迁移入口 `.automaticBySize` 导入体积为 50MB 减 1 字节的记录 | 按历史规则归副本侧；新 UI 不调用该入口 | 旧阈值数据兼容，不代表新入库产品规则 |
| B-05 | 构造回收站条目并将系统时间推进至第 30 天与第 31 天 | 第 30 天仍可恢复；第 31 天已被清除且副本文件已删盘 | 保留期两侧行为（AC-08） |
| B-06 | 打开编辑器不做任何修改后点确认 | `contentHash` 不变，`indexedAt` 不变，未产生任何供应商请求 | 按内容比对而非打开动作判脏（AC-38） |
| B-07 | 编辑器存在未确认改动时点击面板外部 | 出现二次确认，选择放弃才丢弃；面板不自动收起 | 未保存改动的保护（AC-38） |
