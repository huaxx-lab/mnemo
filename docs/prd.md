# PRD: Mnemo 新版本

## 一、项目背景与目标

### 背景

Mnemo 是一款 macOS 原生效率工具，把用户反复使用的内容（文字、图片、链接、PDF、文件）收进 MacBook 刘海，平时隐藏、需要时展开。首版上线两天登上 Mac 效率榜第一。

首版发布后已完成并上线的更新——图片 / 文字 / PDF / 网页直接预览、Pin 后的文字可在刘海中二次编辑、常见文件类型直接拖拽入刘海——本 PRD 视为产品基线。其中**文本二次编辑**在本版本产生了新的耦合：内容变更要触发向量重算，关闭面板时还要保护未确认改动。因此在 F2.8 中重新定义完整规格。

本 PRD 覆盖在此基础上的新版本。

### 技术栈

- SwiftUI + AppKit，最低系统 **macOS 26**
- Liquid Glass：`GlassEffectContainer` / `glassEffect` / `glassEffectID` / `GlassEffectTransition`
- SwiftData 本地持久化；换机与备份使用版本化整库归档（已移除 iCloud / CloudKit）
- Keychain 存储凭据，Vision 框架做本地 OCR
- 第三方 AI 供应商，需同时适配 **OpenAI 兼容**与 **Anthropic Messages** 两种协议方言

### 项目级目标

1. 把 Mnemo 从「能存」推进到「存多了也能认出来、找得到」
2. 引入 BYOK 模式的 AI 能力（命名、分类、搜索、加工），零服务器成本、零登录
3. 完成 macOS 26 Liquid Glass 的视觉与动效适配
4. 增加效率模式（待办 / 番茄钟 / 专注热力图），与收纳共享同一数据源
5. 提供可校验的整库导出 / 导入，不依赖云账号

### 项目级非目标

- 不做 Web 端、iOS 端、Windows 端
- 不自建 AI 中转服务，不代付 token 费用，不做账号体系
- 不做端侧模型（含 Apple Foundation Models）
- 不做团队协作、共享、多人编辑
- 不向下兼容 macOS 25 及以下
- 本版本不做付费墙，但保留授权抽象层

### 与现实的偏差说明

- 供应商价格与模型能力数据依赖第三方开源数据源，存在滞后。App 内置快照 + 异步刷新，极端情况下可能短暂显示过期价格。
- 普通文件默认采用安全书签引用，跨设备只同步元数据；临时图片、剪贴板位图或无法建立可靠书签的来源才创建受管副本。
- 本地敏感内容筛查基于规则匹配，无法覆盖全部敏感语义，不承诺 100% 拦截率。

## 二、功能需求

### 模块 1：刘海交互与视觉

**目标**：在原生 Liquid Glass 之上做出收起 / 展开 / 融合的连贯动效，并承载双模式切换。

**非目标**：不自绘整套玻璃材质、不替换系统拖拽预览；不为无刘海机型追求视觉一致（仅保证功能可用）；不绘制梯形、张力桥或独立的大块拖拽反馈面板。

#### F1.1 收起态统一状态条 [P0]

刘海收起时不区分模式，只显示当前最紧要的一个状态。优先级从高到低：

1. 拖拽悬停中 → 变为投放区
2. 番茄钟计时中 → 显示剩余时间
3. 索引 / 同步进行中 → 显示进度
4. 默认 → 收纳入口

#### F1.2 展开与收起时机 [P0]

- 刘海层只响应**明确点击**或全局快捷键；普通 hover 不展开、不收起，也不改变窗口高度
- 文件、图片、链接或文字拖入刘海命中区时，只展开浅层投放区，不打开完整工作台；移出即恢复，释放后给出吸收反馈
- 卡片单击复制、双击打开预览；取用远比查看频繁，默认动作给取用
- 展开后按关闭按钮、Esc 或点击面板外收起；用户已钉住时，点击面板外不收起；收起不取消正在进行的检索，回来时结果仍在
- 文本存在未确认改动时，任何关闭动作都先二次确认，不静默丢弃
- 卡片详情与编辑器显示在刘海主体下方的独立窗口中，不能与刘海中间的物理缺口或卡片轨道叠在一起

#### F1.3 Liquid Glass 适配 [P0]

- 刘海锚点使用固定尺寸窗口；浅层投放反馈、完整工作台与详情分别使用独立稳定窗口，不能通过缩放同一个 `NSPanel` 切换职责
- 刘海条与浅层投放区可在各自稳定窗口内使用一致的 `glassEffectID` 与形状语言；完整工作台以协调过渡承接视觉，不要求跨窗口执行不可控的 matched morph
- 禁止同时动画 `NSWindow.frame` 与 SwiftUI 内容；窗口先以最终尺寸就位，形变、位移与透明度仅由 SwiftUI 的显式阶段驱动
- 内容卡片、预览区与编辑区使用稳定的实色半透明表面，不叠加玻璃，避免 glass-on-glass 导致文字和缩略图发灰
- 拖拽对象接近刘海时，由专用拖拽接收层处理真实数据；状态反馈只占用刘海左右翼，不创建独立可见 overlay、梯形或张力桥
- 出站拖拽保留原文件名与 UTI；入站只在明确拖拽命中时出现投放区，不能由普通 hover 触发
- 遵循系统深浅色，以及「减弱透明度」「减弱动态效果」辅助功能设置

#### F1.4 双模式切换 [P0]

展开态提供收纳模式 / 效率模式切换（左右滑动手势 + 可点击的模式指示器）。切换状态持久化，下次展开回到上次所在模式。

#### F1.5 边缘状态光效 [P1]

刘海边缘以呼吸光提示状态（计时结束、同步完成、索引失败）。设置中可关闭，并遵循「减弱动态效果」。

#### F1.6 工作台信息层级 [P0]

- 收纳与效率工作台使用同一稳定外框，切换模式不得改变 AppKit 窗口 frame
- 效率页按待办 P0、番茄钟 P1、专注热力图 P2 组织；空待办只保留紧凑空态，不为不存在的数据预留整块列表区域
- 面板宽度按卡片实际排布收敛，不留大片空白；收纳态保持单行横向卡片，多出的高度用于放大缩略图而不是空着
- 链接详情以整块封面呈现：左下角站点图标、标题与完整地址，右上角一排轻量动作（复制、就地看页面、在浏览器打开、关闭）；抓不到封面时用域名徽标铺底，不拉伸站点图标
- 「更多」下拉画在面板内部，不得溢出到刘海与菜单栏上；卡片轨道在项目多于一屏时提供翻页把手
- 工具栏只保留模式、搜索、明确的更多菜单与收起；不可操作的状态不能伪装成图标按钮
- 永久 `+` 不得出现在刘海入口；只有拖拽内容已被系统确认可接收时，才显示添加反馈

### 模块 2：收纳与存储

**目标**：优先保留原文件链接、避免重复占盘，并为删除、离线、内容变化与恢复建立可预测的生命周期。

**非目标**：不做文件夹层级；不做版本历史；不做富文本编辑器（二次编辑限于纯文本）。

#### F2.1 文件存储策略 [P0]

- 普通 Finder 文件不论体积，优先保存安全范围书签并直接引用原文件
- 剪贴板位图、系统临时文件等离开当前操作后可能立即消失的来源，必须先创建受管副本
- 无法建立可靠书签时才降级为副本；副本创建失败则明确报错，不留下半份临时文件
- 卡片明确标注「引用 / 副本」；旧版本的阈值混合策略只作为数据迁移与兼容测试保留，不再驱动新入库决策

#### F2.2 副本去重与引用计数 [P0]

副本以内容 SHA-256 命名存储。同一内容被重复拖入时复用已有 Pin，不新增肉眼相同的卡片；已有 Pin 在回收站时恢复原条目。底层仍通过引用计数管理共享副本，计数归零方可进入回收站。

#### F2.3 回收站 [P0]

删除的条目进入回收站，保留 30 天后自动清除。回收站内条目不进入搜索结果与刘海展示，但**保留其向量**，恢复时无需重算。设置中可查看回收站占用并手动清空。

#### F2.4 引用文件生命周期 [P0]

- 确认源文件已删除时，对应 Pin 自动进入回收站，并冻结其旧向量，不继续参与展示和搜索
- 外置卷未挂载或文件暂时不可达时保留 Pin，不误判为删除，也不反复调用 AI
- 原文件内容发生变化时标脏并串行重建索引；内容未变不更新 `modifiedAt`，不产生同步或 AI 冗余调用
- 同一内容再次拖入时，如果回收站中已有 Pin，则恢复原 ID 与向量，而不是创建重复条目

#### F2.5 孤儿文件对账 [P0]

App 启动时执行一次双向一致性扫描：磁盘上存在但数据库无记录的副本视为孤儿并清除；数据库记录指向的副本文件不存在时，条目转为损坏态并提示。

#### F2.6 存储用量面板 [P0]

设置中显示副本占用总量与回收站占用总量，支持按体积排序查看条目，支持一键清理回收站。

#### F2.8 文本条目二次编辑 [P0]

- 纯文本条目在独立详情窗口内直接编辑，刘海主体保持为导航与卡片轨道
- 编辑区头部显示条目类型与实时字数
- 提供显式的「确认」与「取消」两个动作：取消丢弃全部改动，确认写回
- 编辑期间执行关闭动作时必须保护未确认改动（见 F1.2）
- 确认写回后若内容实际发生变化，`contentHash` 更新、条目标脏并入队重算（见 F5.2）；内容未变则不触发重算
- 存在未确认改动时关闭面板需二次确认，不静默丢弃

#### F2.7 整库导出 [P1]

支持将全部条目（含副本文件、元数据、标签、分组、待办与专注记录）导出为版本化单一归档包并可再导入。安全书签与向量不跨设备导出；导入后按本机配置重建索引。

#### F2.9 剪贴板临时轨道 [P0]

- 自动捕获的未固定截图 / 文字默认只保留，不做 OCR、图片理解或 Embedding；设置开关只影响切换之后的新捕获，固定后或人工拖入 / 显式收纳始终立即处理；已有索引与既有任务不追溯改变

- 系统剪贴板发生真实变化时才读取内容，默认动态保留最近 5 条，可在 1–20 条之间调整
- 被动监听只收截图与文字：复制一个文件通常只是要粘到别处，文件仍在磁盘上，收纳需拖入或显式执行「收纳剪贴板」
- 新内容平滑进入，超过上限只淘汰最旧的未固定临时项；用户固定后的 Pin 永不参与淘汰
- 固定可逆：卡片上的图钉常驻，锁定后点它即放回临时轨道并立即按容量结算
- Mnemo 自己写入剪贴板的动作不得被监听器再次收纳；相同内容不得重复创建卡片
- 临时与固定只决定保留策略，不决定是否调用 AI；所有新内容均按同一去重队列判断是否需要整理与索引

### 模块 3：AI 供应商接入

**目标**：让用户用自己的 key 接入任意供应商，常用供应商开箱即用，成本可预估。

**非目标**：不内置任何免费额度；不做供应商代理；不做端侧模型。

#### F3.1 自定义供应商 [P0]

支持手动添加供应商：名称、协议方言（OpenAI 兼容 / Anthropic Messages）、baseURL、API key、模型列表、鉴权方式。

#### F3.2 常用供应商预设 [P0]

内置常用供应商的图标、baseURL、模型列表与鉴权配置，用户只需填 key。覆盖范围至少包含：OpenAI、Anthropic、Google、DeepSeek、月之暗面、智谱、通义、硅基流动、火山方舟、MiniMax、OpenRouter、Ollama、LM Studio。

#### F3.3 模型元数据与价格 [P0]

- 内置模型元数据快照：供应商、baseURL、模型、输入 / 输出 / 缓存单价、上下文与输出上限、输入模态、是否支持工具调用
- 首次添加或切换供应商时自动获取一次模型列表；之后始终读取本地缓存，不按启动、定时器或设置页打开动作重复请求
- 设置中提供明确的「刷新模型」按钮。刷新期间继续展示旧缓存；新响应完整校验成功后一次性原子替换，失败时保留旧缓存并显示原因
- 设置中展示每个模型的单价与能力标签
- 供应商官方模型列表与 models.dev 能力 / 价格快照各有独立的用户主动刷新按钮；二者都不能按启动、定时器或设置页打开动作刷新
- models.dev 只补齐已适配供应商中同名模型的 chat 元数据，不得把公共目录误当成当前账号实际可用模型列表
- **chat 侧与 embedding 侧使用各自的元数据来源**。任一侧数据缺失时，该侧退化为手动填写模型名，不影响另一侧

#### F3.4 能力门控 [P0]

依据模型的输入模态禁用不支持的功能入口（如所选模型不支持图片输入时，图片相关 AI 功能置灰）并说明原因。不允许用户点击后才报错。

#### F3.5 成本预估 [P1]

设置中按当前分级路由、实际单价与本机累计 usage，展示「自动命名每 100 条约 ¥X」「语义搜索每次约 ¥X」。供应商未返回 usage 时显示估算基线；Embedding 单价允许手填，不从不完整目录推断。

#### F3.6 凭据安全 [P0]

API key 仅存于 Keychain。禁止写入 UserDefaults、plist、任何日志或崩溃上报；调试输出对 key 做脱敏。

#### F3.7 独立的 embedding 供应商配置 [P0]

embedding 供应商与 chat 供应商分开配置。未配置 embedding 时，语义搜索入口不可用并说明原因。

- embedding 模型名**必须支持手动输入**，不能只提供下拉选择——公开目录对 embedding 模型的覆盖极不完整
- 首次使用某个 embedding 模型时**运行时探测输出维度**并记录，不预设维度
- 已记录的维度与实际返回长度不符时，判定为模型变更（见 F5.2）

### 模块 4：AI 能力

**目标**：解决「存多了认不出、找不到」，同时保证敏感内容不出本机。

**非目标**：不做对话式助手；不做内容生成 / 创作；不做任何自动修改用户文件的操作。

#### F4.1 分级路由 [P0]

设置中区分「快模型」与「强模型」两档并分别绑定模型。自动命名、自动分类、场景识别与查询解析默认走快模型；PDF 问答、粘贴加工默认走强模型。每个 AI 功能均可独立覆盖供应商、模型与思考强度，并明确显示「继承」或「自定义」。思考强度仅在所选模型与协议方言支持时可选；不支持时入口置灰并说明原因。

#### F4.2 本地敏感内容筛查 [P0]

任何内容外发前先经本地规则筛查。命中身份证号、银行卡号、手机号、API key、密码特征的内容不外发，退回本地规则命名，并在卡片上标注「本地处理」徽标。筛查在本机执行，不依赖网络。

#### F4.3 自动命名与分类 [P0]

Pin 入库后自动生成简短标题与分组归属。未配置 AI 时回退为文件名 / 网页标题 / 文本首行。

#### F4.4 语义搜索 [P0]

搜索框接受自然语言。输入时先用本地规则即时筛选，不产生网络请求；用户按回车主动提交后，才由查询解析路由将查询拆成**结构化条件**（时间范围、内容类型、标签）与**语义部分**，随后对候选集做一次查询向量匹配。相同查询与路由复用本机缓存；未配置或解析失败时退回本地全文搜索。示例：「昨天那个跟报销有关的截图」。

#### F4.5 截图 OCR [P1]

图片类条目入库时由 Vision 框架在本地提取文字，纳入全文与语义索引。不外发。

#### F4.6 粘贴加工 [P1]

取用条目时可按目标场景加工输出（如只取税号、转为纯文本、翻译）。走强模型。

#### F4.7 PDF 问答 [P2]

对 PDF 类条目直接提问。走强模型，受 F3.4 能力门控约束。

#### F4.8 详情动作与剪贴板上下文推荐 [P0]

详情动作建议与顶部上下文推荐是两条独立流程。详情页可按当前 Pin 类型展示复制、预览、OCR、问答等动作；打开详情不得触发重新命名或重复索引。详情是带独立关闭键的窗口：收起刘海工作台或点击外部应用时，预览或编辑详情都继续留在屏幕上，只有用户点详情关闭键（或切换模式、条目被删除）才关闭；正在编辑且有未保存内容时，详情自己的关闭键仍走确认流程。

被动剪贴板与主动推荐分离：外部复制只做收纳和“这是不是检索请求”的去留判断，不触发推荐；本地确定性规则先判，认不出但像短诉求时用 LLM 兜底，模型不可用或不确定时保留文字。用户在任意应用选中文字按 ⌘G 才启动快捷推荐；代按 Cmd-C 登记为自写，不创建 Pin、不展开工作台，结果直接落在刘海。检索链为：本地结构化理解 → 已配置的查询 Embedding + 本地全文 / OCR / PDF 分块召回 → 控制器通过覆盖文档、图片、网页、表格、日志、代码和普通文字的成对 Few-shot，按用户最终想得到原对象 / 原值还是解释 / 分析，只能在真实候选 ID 内输出互斥的 `retrieve / answer`。`retrieve` 交付真实 Pin 或经本地逐字校验的局部原值；`answer` 把白名单 ID 仅作内部证据，不同时显示文件卡；重读完整本地分块，生成完整简体中文回答。设置项“聚焦输入框时直接写入”默认开启：按快捷键时若焦点是可写的外部文本输入框（排除 Mnemo 自身、只读控件和密码框），回答通过 SSE 分段写在选区末尾；否则整段确认完整后写入剪贴板。输入框写入期间若焦点 / 光标 / 选区变化或 AX 写入失败，立即停止并把当前结果放进剪贴板；模型截断或网络中断时，若用户未移动光标则撤回 Mnemo 插入的半成品，绝不冒充完整。写失败保留手动重试，过期回答不得覆盖。回答卡无叉号，点击外部自动收起，自绘细滑块无槽无边框地悬浮在正文边界，正文始终裁剪在标题下方。Command-G 不设冷却期；每次按键创建新 generation，取消尚未完成的旧选区抓取并只发布最新一次。 Command-C / 选中自动复制与 Command-G 不互斥：优先直接读取当前 AX 选区；否则接受新剪贴板写入、选中时已有的外部文字，或同一前台应用上次显式验证的选区。Mnemo 上轮回答不得冒充选区。每轮消息与工具状态独立，不保存对话历史；供应商明确因 token 上限截断时不得发布半句答案。

自动写入剪贴板有两类资格：本地字段、精确标识或全库类型唯一；或模型在真实候选内**恰好收敛到一条**且该条命中请求点名的类型或带本地证据。敏感字段（银行账号、证件号）一律不自动写；模型给出多条时只推荐，由用户点选，自报置信度不是授权。异步文件 URL 解析与粘贴板写入成功后才显示对号。本地已判定为检索请求的复制**不入库**，不占用最近五条；Mnemo 自写的全部 `changeCount` 不得再次触发捕获。

#### F4.9 AI 调用时机与去重 [P0]

- 新增、真实内容编辑或 embedding 模型变化时才进入整理 / 索引队列；回收站恢复沿用已有结果。打开详情只允许 F4.8 在缓存缺失时按内容版本调用一次，绝不触发命名、分类或索引；hover、搜索框聚焦和索引字段回填不得触发调用
- 命名与分类使用相同路由时合并为一次结构化请求；同一 Pin 同一内容版本在队列中只允许存在一次
- 队列持久化且串行执行。离线时冻结，网络从不可用恢复时只唤醒一次；无效 Key 或配置错误暂停，等待用户修正，不循环重试
- 结构化响应仅在请求成功但格式错误时修复一次；回收站冻结向量，恢复时沿用，避免重复 token

### 模块 5：向量索引

**目标**：向量与条目在增删改及换模型时始终保持可追踪的一致状态，且不阻塞用户操作。

**非目标**：不引入向量数据库；不做跨设备向量同步；不做混合检索的排序调优。

#### F5.1 索引字段 [P0]

每个条目存储四个字段：`vector`、`contentHash`、`embeddingModelID`、`indexedAt`。

#### F5.2 增量索引触发 [P0]

- **新增**条目 → 入队
- **编辑**导致 `contentHash` 变化 → 标脏并入队
- **删除**条目 → 级联删除向量，不留孤儿
- **切换 embedding 模型** → `embeddingModelID` 不匹配的条目全部标脏并入队

#### F5.3 索引队列 [P0]

队列串行执行，可中断、可续跑，展示进度。无网络、无 key 或供应商报错时任务保留在队列中，条件恢复后自动继续，不丢任务。

#### F5.4 脏数据检索行为 [P0]

检索时对已标脏但存有旧向量的条目，使用旧向量参与匹配，结果中标注「索引中」。不得因正在重算而将条目排除在结果之外。

### 模块 6：效率模式

**目标**：把「收进来的东西」和「要处理的事」合并成一个数据源，让 Pin 顺手变成待办。

**非目标**：不做项目管理、子任务、依赖关系、协作分配；不做日历集成；不做番茄钟的深度统计报表。

#### F6.1 待办与收纳打通 [P0]

待办列表由两部分组成：被标记为待办的 Pin 条目，以及不关联任何 Pin 的纯文字待办。二者共享同一存储、同一同步、同一搜索。

#### F6.2 卡片转待办 [P0]

任意卡片可一键标记为待办，支持设置截止日期与完成状态。完成后条目本身仍保留在收纳库中。

#### F6.3 番茄钟 [P1]

可设置时长的专注计时。计时中，收起态刘海条显示剩余时间（见 F1.1 优先级）。支持暂停、继续、放弃。

#### F6.4 专注热力图 [P2]

以贡献图形式展示每日专注情况。

---

### 模块 7：本地迁移与备份

**目标**：不依赖 iCloud / CloudKit，在用户明确操作时完整迁移数据。

#### F7.1 版本化整库归档 [P1]

导出与导入条目、受管副本、标签、分组、待办和专注记录；导入前校验副本哈希。安全书签、向量与 Keychain 凭据不跨设备迁移；导入后按本机配置重建索引。


### 模块 8：授权抽象层

**目标**：本版本全部功能免费开放，同时为未来的付费墙留出改动面最小的接口。

**非目标**：本版本不接入 StoreKit，不做购买、恢复购买、试用期。

#### F8.1 授权判断抽象 [P1]

所有未来可能付费的功能（AI、同步、效率模式）统一经过一个 entitlement 判断入口，本版本恒返回「已解锁」。

#### F8.2 早期用户标记 [P2]

记录首次启动时的版本号，用于未来兑现「首批用户永久解锁」的承诺。
