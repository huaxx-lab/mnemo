## 1. 交接目标

下一位 Agent 需要接手 Mnemo 的整体重构与验收。当前工程已经具备较完整的数据、文件生命周期、AI 供应商、索引和窗口基础，但真实刘海屏交互与最新的“场景识别”产品定义尚未完成。不要继续在现有截图问题上逐个打视觉补丁；先统一状态机、窗口职责、布局约束和交互所有权，再完成真实桌面验收。

本文件区分三种状态：

- **已实现并自动验证**：已有代码，且当前测试套件覆盖对应核心行为。
- **已实现但未完成真实验收**：代码存在或编译通过，但仍须在真实 Finder、浏览器、截图拖拽和刘海屏上验证。
- **尚未实现 / 旧理解错误**：不得宣称完成，必须先更新规范再开发。

## 2. 最新产品真相（覆盖旧实现与旧文档）

### 2.1 展开形态

- 收起态常驻刘海左右翼，必须点击才展开；普通 hover 不展开。
- 展开工作台在视觉上必须是刘海自然生长出的一个整体，不能像刘海下面另弹出一个悬浮窗。
- 内部可以继续采用多个 `NSPanel` 隔离点击、拖拽与详情职责，但用户可见轮廓、底色、圆角、接缝和动效必须是一体的。
- 详情是独立窗口，和刘海工作台分开；打开详情不得改变工作台几何。预览与编辑详情都自带关闭键，刘海工作台收起后继续留在屏幕上，直到用户明确关闭；编辑详情在自己的关闭流程中保护未保存内容。
- 顶部应有 Mnemo 系列应用图标和可发现的菜单栏入口，方便打开、设置和退出。
- 展开只有一个事件所有者：AppKit 按共享 metrics 接管展开唇、推荐行与关闭区，SwiftUI 只绘制；这保证非激活面板在其他应用前台时第一次点击也有效。

### 2.2 拖拽

- 用户从 Finder、浏览器、聊天软件或截图工具拖入文字、图片、文件、链接时，靠近刘海即由 Mnemo 自己识别内容类型。
- 不常驻显示手工“+”入口；有效拖拽靠近时，刘海左翼显示添加符号，右翼显示识别出的类型图标。
- 反馈只发生在刘海左右翼；不显示独立的大块“松手收纳”面板、梯形或张力桥。
- 图片 / 截图必须和文字一样触发有效投放态；系统拖拽预览本身不能被误认为 Mnemo 的界面。
- 拖拽接收区要在光标触及系统顶部热区前接住事件，避免触发 Mission Control / 切换桌面。
- 同一拖拽会话只能入库一次；重复内容恢复或复用原 Pin，不能新增重复卡片。

### 2.3 剪贴板临时轨道

- 剪贴板条目与其他 Pin 使用同一列表、同一卡片和同一分类，不单独占一行。
- 默认保留最近 5 条未固定内容，仅按数量动态滚动淘汰；没有时间 TTL。
- 固定后升级为普通 Pin，不参与容量和时间淘汰。
- Mnemo 自己写回剪贴板的内容不得再次被监听器捕获。
- 重复内容复用原条目；回收站条目再次出现时恢复，向量先复用 / 解冻，内容真实变化才重建。

### 2.4 被动剪贴板与 Command-G 快捷推荐

被动剪贴板与主动推荐已经拆开：

- 被动监听只保留截图 / 图片和普通文字；文件不自动入库。
- 被动复制**不触发推荐**。文本只经过本地规则与 LLM 兜底分类，决定它是否是检索请求、是否应从最近五条撤掉；不确定或模型不可用时保留。
- Command-G 读取前台应用当前选区，不创建 Pin、不打开完整搜索工作台，结果直接从刘海显示。
- Mnemo 代按 Command-C 产生的 changeCount 会被登记为自写，不能再次触发被动收纳。

Command-G 采用有界推荐 Agent：

1. 本地查询理解 + Embedding RAG 召回真实候选。
2. 控制器用跨文档、图片、网页、表格、日志、代码和普通文字的成对 Few-shot，按“最终要原对象 / 原值，还是解释 / 分析”在候选 ID 内输出 `retrieve` 或 `answer`。
3. `retrieve`：交付真实文件 / 图片 / Pin；若只要网址、单号等局部值，模型只能指认本地原文，`CopyPayloadResolver` 逐字校验。
4. `answer`：候选 ID 只作内部证据，不显示文件卡；按选中 ID 重新读取完整本地分块，不使用 180 字候选摘要或 400 字 `copyText`；生成完整简体中文回答；默认在按键时若聚焦外部可写文本输入框则通过 SSE 直接分段写入，否则整段写入剪贴板。设置中可关闭直接写入；密码框、只读控件、Mnemo 自身控件和焦点改变都安全回退。成功才显示对应确认，失败保留手动复制重试。Markdown 无描边显示，自绘细滑块悬浮边界且无滚动槽，点击面板外收起且无叉号；正文裁剪在标题下方，自绘细滑块无槽悬浮右边界。
5. OpenAI `finish_reason=length` 与 Anthropic `stop_reason=max_tokens` 均视为未完成，半句答案不发布。

状态与安全边界：

- 每次调用创建全新的 system/user 消息；不保存对话 history，不跨轮保留 messages / tool state。
- 只有当前 Task 的候选 ID、工具证据和回答存在；进程内最终决策缓存不进入下一轮 prompt。
- LLM 不能创造候选 ID、文件或字段值；模型置信度本身不是自动执行授权。
- 不自动提交表单、不上传文件、不点击第三方页面、不改写源文档。

### 2.5 搜索

- 搜索不是普通关键词筛选，也不是让 LLM 凭空回答。
- 明确链路应为：查询理解（本地 + 可选 LLM）→ embedding / 本地 RAG 召回 → LLM Agent 在候选内重排与解释 → 直接推荐真实 Pin。
- LLM 只能返回候选 ID，不得发明库中不存在的条目。
- 论文要支持按自然语言描述召回相关 PDF / 页块；图片要支持 OCR 与本地视觉标签召回。
- 没有配置 LLM 时仍应保留本地全文 / 结构化 / 已有向量检索的可用降级路径。
- 主动刷新由用户点击按钮触发；模型目录、官方模型列表和能力元数据不得在页面出现或启动时反复刷新造成抖动。

### 2.6 文案与控件尺寸

- 模型理由必须在数据边界和 UI 两层限制长度。
- 顶部 / 详情推荐控件必须有固定或有上限的宽高；最多两行理由，尾部截断，完整理由放 tooltip / 详情。
- `SuggestionRow` 与搜索卡片已限制标题 / 理由长度和尺寸；最终安装包仍需用超长真实模型输出复核。
- “展开”不能同时存在 AppKit 命中层和 SwiftUI `Button`。只保留一个明确命中区，视觉层不得再次接管点击。
- 图标必须有 tooltip；删除应在卡片 hover、右键菜单和键盘路径中可发现，不使用含义不明的无标签图标堆叠。
